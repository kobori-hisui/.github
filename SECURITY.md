# Security Policy

## Supported versions

Only the **latest released version** of each project receives security fixes. Please update before reporting.

## Reporting a vulnerability

**Do not open a public issue, pull request or discussion for a security problem.**

Use GitHub's private reporting instead:

1. Open the affected repository.
2. Go to the **Security** tab.
3. Choose **Report a vulnerability** and fill in the form.

If you cannot use that form, email **CONTACT_EMAIL** with the subject `Security: <repository>`.

Please include:

- the affected project and version;
- a clear description of the problem and its impact;
- step-by-step instructions or a proof of concept to reproduce it;
- any suggested fix, if you have one.

## What to expect

These are best-effort targets for a small team:

- Acknowledgement within **7 days**.
- A first assessment (accepted, needs more information, or declined) within **14 days**.
- A fix or mitigation as soon as it is practical, depending on severity.
- Credit in the release notes if you want it.

## Disclosure

Please give us a reasonable time to release a fix before sharing details publicly. We will coordinate the disclosure date with you.

## Scope

In scope: code in this organization's repositories and the browser extensions we publish, including permission handling, data stored by the extension, and communication with external services.

Out of scope: vulnerabilities in third-party websites or services (report them to their owners), social engineering, and issues that require a compromised device or browser profile.
